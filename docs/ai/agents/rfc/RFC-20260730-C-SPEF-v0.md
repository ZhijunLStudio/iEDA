# RFC-20260730-C-SPEF-v0 — post-route SPEF 产物与门禁契约（草案）

| 字段 | 值 |
|---|---|
| 契约 ID | C-SPEF |
| 作者 | A2 rcx |
| 需要 ACK | A0 + A3 + A1 |
| 状态 | accepted-draft（A1：flow 契约 ACCEPT；trusted SPEF 仍堵 ITF） |
| 目标 Wave | Wave-0（WP-RCX-01 / WP-STA-01） |

## 变更动机

AES13 flow 历史上 routing 后直接 STA，路径 `net delay=0`。需在 routing 与 timing 之间强制可机读 SPEF 产物，并区分 **ircx / fallback_proxy / missing** 来源，禁止 silent skip。

## 载荷 Schema（v0）

### `result/rcx/rcx_coverage.json`

```json
{
  "schema": "c-spef/v0",
  "design": "aes_sky130_a",
  "pdk": "sky130",
  "source": "ircx|fallback_proxy|missing",
  "trusted": false,
  "spef_file": "/abs/path/to/design_corner.spef",
  "spef_files": [],
  "require_spef": false,
  "warnings": [],
  "pdk_files": {
    "mapping_file": "/abs/path/rcx_layer_mapping.txt",
    "itf_file": "",
    "captab_file": "",
    "ready": false
  },
  "gaps": ["ITF missing: ...", "captab missing: ..."],
  "stage_status": "success|skipped|failed"
}
```

### Flow 环境变量

| 变量 | 含义 |
|---|---|
| `SPEF_FILE` | timing/power 读入的 SPEF 绝对路径 |
| `SPEF_SOURCE` | `ircx` / `fallback_proxy` / `missing` |
| `IEDA_REQUIRE_SPEF=1` | SPEF 缺失时 timing/power Tcl 非零退出 |

### SPEF 文件命名（iRCX `report_rcx`）

`{output_dir}/{design_name}_{corner_technology}.spef`（见 `SpefDumper.cc`）。

## A1 标签规则（v0）

| `source` | `trusted` | A1Verdict 上限 |
|---|---|---|
| `ircx` + G8 未过 | false | `proxy`（net delay 可非零但仍非 signoff） |
| `fallback_proxy` | false | `invalid`（仅读链 smoke） |
| `missing` | false | `invalid` / stage FAIL（`--require-spef`） |

**禁止**将任意 SPEF 存在等同于 WNS `trusted`。

## 兼容性

- 默认：rcx PDK 未就绪 → stage `skipped`，timing 行为与旧 flow 相同（无 SPEF）。
- `--require-spef`：Wave-0 强制；缺 ITF 或缺 SPEF → 非零退出。
- `--skip-rcx`：显式关闭 rcx，恢复 legacy。
- `--fallback-spef`：仅 sky130 有 `Foundary/sky130/spef/gcd.spef`；必须写 `warnings` 且 `trusted=false`。

## 回滚

移除 `STAGES` 中 `rcx` 条目，或全程 `--skip-rcx`；timing 脚本 SPEF 块由 env 控制，无 SPEF 时不执行。
