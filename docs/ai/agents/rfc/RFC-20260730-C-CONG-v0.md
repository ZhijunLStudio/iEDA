## 变更动机

AES12 报告显示 `Average Congestion = -1`，但 `result/egr_congestion_map/place_egr_*_overflow.csv` 与 early-router `overflow_map_*.csv` 有效。

根因（H1 已确认）：

1. **路径不一致**：EGR CSV 经 `createDirPath("/egr_congestion_map")` 写入 `output_path/egr_congestion_map/`（`feature_path` 空时回退 `output_path`），而 `getDefaultOutputPath()` 原先仅读 `feature_path`，导致 `CongestionEval::eval*Overflow()` 在 report 时刻找不到 CSV，返回 **-1 sentinel**。
2. **报告层未过滤 sentinel**：`PLReporter::reportCongestionInfo` 曾直接 `std::to_string(-1)`；`OverflowSummary` 默认值亦为 -1。
3. **汇总与 map 解耦**：门禁脚本已能读 CSV（`quality_metrics.parse_overflow_csv`），但 flow 报告仍走失效 API 路径。

本 RFC 引入 **C-CONG v0**：以 EGR CSV 为 source-of-truth 写出 `result/congestion_summary.json`，report / 门禁优先读 JSON，彻底消灭 -1 进入签核面的路径。

## 载荷 Schema（前后对比）

### Before

- 唯一汇总：`report/congestion.rpt` 表格行 `Average Congestion | Total | Max`
- 失败语义：`-1` 或 `N/A` 混用；解析器需 `average >= 0` 才 valid
- 无机器可读汇总 JSON

### After（C-CONG v0）

路径：`{output_path}/congestion_summary.json`

```json
{
  "schema": "C-CONG",
  "schema_version": 0,
  "stage": "place",
  "source": "egr_csv",
  "valid": true,
  "generated_at": "2026-07-30T12:00:00Z",
  "maps": {
    "horizontal": {
      "path": ".../place_egr_horizontal_overflow.csv",
      "bin_count": 22200,
      "total": 123456,
      "max": 54,
      "mean": 5.56,
      "top_1_pct_mean": 42.1,
      "top_5_pct_mean": 28.3,
      "nonzero_bin_pct": 39.89,
      "weighted_average": 761.75,
      "valid": true
    },
    "vertical": { "...": "..." },
    "union": { "...": "..." }
  },
  "summary": {
    "average_edge_congestion": 3904.30,
    "total_overflow": 194936,
    "max_overflow": 76,
    "mean": 8.78,
    "top_1_pct_mean": 52.4,
    "top_5_pct_mean": 31.2,
    "nonzero_bin_pct": 47.35
  }
}
```

字段约定：

| 字段 | 含义 |
|---|---|
| `summary.average_edge_congestion` | 与 legacy report 一致的 **weighted top-bin 平均**（`evalUnionAvgOverflow`） |
| `maps.*.mean` / `top_*_pct_mean` / `nonzero_bin_pct` | 与 `quality_metrics.parse_overflow_csv` 一致，用于 G5 门禁 |
| `valid` | 三方向 CSV 均可解析且 weighted 指标非负；**JSON 内禁止出现 -1** |

写入时机：`report_congestion` → `ReportEvaluator::createCongestionReport()` 在 `egrMap("place")` 之后。

读取优先级：

1. `congestion_summary.json`（C-CONG）
2. `egrOverflow()` API（修复路径后）
3. 解析器对 legacy `congestion.rpt` 中 `-1` 仍标 `valid=false`（E-MAP-01）

## 兼容性 / 迁移

- **向后兼容**：旧 run 无 JSON 时，Python 仍解析 `congestion.rpt`；C++ report 仍 fallback `egrOverflow()`。
- **无需重跑**：可对已有 `egr_congestion_map/*.csv` 离线调用 `writeCongestionSummary` 补写 JSON（见 A5 日报验证命令）。
- **非目标**：本 RFC 不改 DR 外环（WP-RT-01）、不改 early-router map 生成逻辑。

## 杀死实验或回滚方案

| 实验 | 预期 |
|---|---|
| E-MAP-01 | 全零 CSV → `nonzero_bin_pct=0`，`valid=true`，不得拉伸伪热点 |
| E-MAP-02 | 删除 CSV 仅留 JSON → report 仍可读；删 JSON 留 CSV → 可重建 JSON |
| H1 对照 | 修复 `getDefaultOutputPath` 后，同 run 的 API 与 CSV 聚合 `total/max` 一致 |
| 回滚 | 移除 `writeCongestionSummary` 调用；解析器继续拒绝 `-1` |
