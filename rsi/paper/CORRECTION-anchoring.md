# Correction: the external anchoring was measured on a regressive generation path

Found on 2026-09-17 while establishing a baseline for source-level iteration.

## What was wrong

The paper's external-anchoring section reports, for the 32 designs with a commercial
reference DEF:

    ruler-optimal pick    0.935x reference wirelength   1.228x reference congestion
    cheap-rung attractor  1.089x                        2.902x

Both picks came from the Stage 1 candidate pool, and every candidate in that pool was
generated by gp_agent.py start with explicit knobs (--target-density, --congestion-effort,
--iterations) and defaults for everything else.

Two things are wrong with using that pool as the representative of "what iEDA does":

1. start is session-mode global placement with a knob set the project's own iteration
   ledger already flags as regressive. Verbatim from POINT_TOOL_ITERATION_LEDGER.md,
   item 8: "timing=1 side effect: unconditional timing=1 causes wirelength regression".
2. start defaults random_init=1, i.e. it places from a random initial placement rather
   than from the input floorplan. That is a harder task than the one the reference was
   produced for.

The plain command exists precisely to avoid this ("placer_run_gp (NO cli knobs, uses the
config's target_density/max_iter as-is) -> LG -> DP"). It is the project's known-good path.

## Size of the effect

Same design, same evaluator, same seed, three generation paths:

| design | plain (config) union / max | start random_init=0 | start random_init=1 |
|---|---|---|---|
| salsa20_nangate45_a | **1090 / 14** | 2714 / 31 | 2760 / 28 |
| s38584_nangate45_a | 21 / 4 | 19 / 3 | 31 / 2 |
| s1238_nangate45_a | 4 / 2 | 2 / 1 | 9 / 5 |
| s1238_sky130_a | **3840 / 66** | (run failed) | 2064 / 36 |
| gcd_sky130_a | **2526 / 32** | 775 / 19 | (run failed) |

And against the Stage 1 pool, whose best knob setting for these designs was:

| design | pool best union | plain union | reference | pool ratio | corrected ratio |
|---|---|---|---|---|---|
| salsa20_nangate45_a | 39644 | **1090** | 250 | 158.6x | **4.4x** |
| s38584_nangate45_a | 3753 | **21** | 6 | 625.5x | **3.5x** |

So the two "congestion catastrophes" that the goal was set up to eliminate are, to a
large extent, an artifact of how the candidates were generated. The real gaps are 3.5x
and 4.4x, not 159x and 625x.

## Corrected standing (plain flow, 12 matched designs = 4 circuits x 3 PDKs)

| dimension | corrected median | better than reference | previously reported |
|---|---|---|---|
| HPWL | 0.945x | 9 / 12 | 0.935x (20/32) |
| EGR union | 1.069x | 5 / 12 | 1.049x (14/32) |
| **EGR max** | **1.343x** | **3 / 12** | 1.956x (8/32) |
| all three no-worse | 3 / 12 | | 8 / 32 |

The corrected numbers are computed on a different design set (the 12 matched designs, not
all 32), so the two columns are not directly comparable in magnitude. A corrected
32-design baseline is being collected; the corrected column here is the 12-design subset.

## What this does and does not invalidate

**Not invalidated.** Every verifier-fidelity finding is a property of a pair of rungs
applied to a set of placements, and is independent of how those placements were generated:
the pre-LG HPWL anti-correlation (-0.891), the selection regret (+19.7% wirelength,
+124.7% congestion within the pool), the dynamics result that cheap-verifier loops end
worse with r* = 0, the mechanism accounting, the scheduling result, the split and transfer
results. Those all compare candidates against each other inside one pool.

**Invalidated.** Any statement whose magnitude is "ours versus the commercial reference",
because the numerator was drawn from the regressive pool. That is the absolute ratios in
the anchoring section, and the "all dimensions no-worse" count.

## Action

1. Recompute the anchoring on the plain flow. A 32-design plain baseline is running.
2. Keep reporting both, labelled by generation path, or report only the plain one.
3. For source-level iteration, the baseline is the plain flow, because it is the path a
   normal GP -> LG -> DP run takes and the one the reference is comparable to.

## Lesson recorded

This is the same class of error the campaign already hit twice: a result that looks
plausible rather than one that breaks. The candidate pool was internally consistent, so
every within-pool comparison was valid, and the flaw only became visible when the pool
was compared against a differently-generated baseline. It is recorded here rather than
quietly recomputed.
