## 1. 十句话讲清这套东西

1. **目标**：在 15 个网表严格匹配的设计上，五个维度（HPWL / EGR union / EGR max / setup WNS / setup TNS）**每个设计、每个可测维度都不高于 Innovus**。
2. **手段**：只改 iEDA 的**源码（算法/方法层）**。编排（跑流程、跑评测、落盘）是机械执行，**不做候选挑选、不做参数搜索**。
3. **闭环**：读评测结果 → 定位**具体**缺陷 → 改源码 → 用**标准全流程 gp→lg→dp** 复测 → 归因 → 找下一个缺陷。
4. **验证器是命门**：结论的可信度上限 = 验证器的保真度。本工作的核心工程就是把验证器从「未合法化线长」抬到「试布线拥塞 + iSTA 时序」。
5. **尺子只有一把**：我方与 Innovus 两侧**在同批次合法化、同一评测器打分**；参考**必须合法化后**才计分。
6. **已定位的核心缺陷**：iEDA 的详细布局（DP）**只看线长**，对拥塞无感知；而**标准流程只跑一遍 LG + 一遍 DP**，从不让这一对收敛。
7. **在树里的改动 3 处**：SR-10（引入拥塞测量）、SR-11（DP 支配性守卫）、SR-21（多跑几遍 LG+DP 并保留最好一遍）。
8. **效果是单向交易**：拥塞明显改善（union 8/13 变好、峰值 9/13 变好，平均收窄 ~16%），**代价是线长（10/15 变差）与时序（3 个设计变差）**。
9. **全维度通过**：三维 3/15 → **4/15**；五维（7 个 sky130）0/7 → **1/7**；含 SR-21 已测设计 → 5/15。
10. **未达成**：**拥塞仍是唯一系统性失分维度**，union 失 8/13、峰值失 8/13。本次改动**收窄了它，没有解决它**。

## 4. 有用的：4 项

### 4.1 SR-10 —— 把拥塞测量引进流程（**地基**）

- **位置**：`PLAPI`，DP 前后调 `notifyPLCongestionInfo` → 试布线 EGR → `PlacerDBInst.egr_tof/egr_mof`。
- **价值**：没有它，后面一切"以拥塞为门"的想法都无法实现。**它自己不改结果，只让结果可被测量。**
- **成本**：每次测量约 2.5 分钟（试布线）。

### 4.2 SR-11 —— DP 支配性守卫（Pareto 安全网）

- **规则**：`若（DP 后峰值变差）且（DP 后总溢出未改善）→ 回退到合法化结果`。
- **价值**：DP 的接受判据（线长）与目标（拥塞）**不一致**，守卫在确凿变差时兜底。
- **诚实的特性**：约 **1/3** 种子触发，**其余逐字节不变** —— **它不提升均值**。
- **代价**：回退会带来线长损失（这解释了 §5.3 的线长变差）。

### 4.3 SR-21 —— 多遍历 + 保留最好（**当前最有希望的**）

- **位置**：`PLAPI::runGatedFinish`，从 `PlacerIO::runDetailPlacement()` 调用 —— **`placer_run_dp` 命令真正落到的地方**。
- **逻辑**：最多 2 遍额外 LG+DP；每遍后**记录整个布局状态**与两个拥塞数；最后**回退到最好一遍**（峰值优先、总溢出次之）。
- **为什么不能"逐步守门"**：实测轨迹**非单调** ——

  | 遍历 | 峰值 | 总溢出 |
  |---|---|---|
  | 1（出厂） | 3 | 37 |
  | 2 | **6**（变差） | 27 |
  | 3 | **2**（最好） | **16** |

  **峰值先降后升**；要求"每步不变差"的规则会拒绝第 2 遍，**而第 3 遍的收益正来自第 2 遍**。
- **已测效果**：

  | 设计 | 无 SR-21 | 有 SR-21 | 结果 |
  |---|---|---|---|
  | **gcd_ics55_a** | union 1.85（失分）| **0.80（通过）** | **失分 → 全通过** |
  | s5378_sky130_b | 1.5597 | **1.5399** | 微改善、无回归 |
  | s1238_sky130_a | 2.0525 / 1.8571 | **完全相同** | **拒绝了有害遍历** |

- **代价**：每遍 = 1 次合法化 + 1 次详细布局 + **2 次试布线评测**，实测**约 6 分钟/遍**；用满 2 遍约 3 倍后置时间。

### 4.4 仪表（不是算法改动，但救了四次）

- **每遍一行日志**（遍号 + 两个拥塞数 + 线长）—— 让"改动是否真的执行"**一次运行就能看出来**。
- 这条规矩在 SR-18 上直接生效：**一个完成的运行打出 0 行日志 → 立刻判定它从未执行**，
  而不是花一小时等结果。
- **教训**：**先加仪表，再谈效果。**

2. **比较的两个二进制必须同提交构建、只差被测改动**，且**比较前先列清每个二进制里有什么**。

3. **只在网表严格匹配的设计上下结论** —— 24 个 sky130 参考 DEF 里 **17 个是不同网表**。
4. **禁止用 GP 阶段数字下结论** —— pre-LG 与 post-LG+DP 的线长相关系数 **ρ = −0.891**（负相关！）。
5. **不把配置差、噪声、候选挑选当改进。**

9. **先数执行次数，再读效果** —— 见 §5.3。

## 7. 环境地雷（**操作层最容易踩，已踩过多次**）

### 7.1 日志不在运行目录里

> iEDA 的 glog 会**重新初始化到 `/var/tmp/`**。运行目录 `<run>/pl/log/info_*` 里**只有 3 行头**。

- **症状**：读运行目录日志，`grep -c 'Start Detail Placement'` 得 0，误判"卡死"。
- **正解**：**按 PID 找日志** —— `ls /var/tmp/info_*.<pid>`。
- **已因此误判两次**（一次把运行中的进程当卡死杀掉）。

### 7.2 `/etc/ld.so.preload` 拦截（目录名含 `log` + exec 路径）

> 宿主装的 `sshdd.so` 拒绝创建**路径含小写 `log`** 的目录，**并且干扰 exec 路径**。

- **症状 A**：`cannot create directories: Permission denied`，卡在 `<out>/pl/log`、`<out>/rt/rt_temp_directory/topology_generator`。
- **症状 B**：`collect2: fatal error: cannot find 'ld'`；`gcc: cannot execute 'cc1'` —— 而 `ld` 与 `cc1` **都存在且可读**。
- **正解 A**：用 **bwrap 包装器**遮蔽 preload 文件 ——
  `build/bin/iEDA-nosshim` = `exec bwrap --dev-bind / / --ro-bind /dev/null /etc/ld.so.preload <真 iEDA> "$@"`
  （由 `rsi/harness/make_ieda_nosshim.sh` 生成）
- **正解 B**：构建时设 **`COMPILER_PATH`** ——
  `COMPILER_PATH=/usr/bin:/usr/lib/gcc/x86_64-linux-gnu/10 cmake --build build --target iEDA`
- **注意**：`bwrap` 对 gcc **无效**（拦截不止走 preload），所以两个正解分别用。

### 7.3 线程数会改变求解轨迹（**必须锁**）

> 树里 50 个 `pragma omp parallel` 区域中有 **48 个没指定 num_threads**，会继承可见核数；
> 并行归约会重排浮点加法 → **改变求解轨迹**。实测同一二进制同一输入：32 核 8185835、64 核 8595054。

- **正解**：`OMP_NUM_THREADS=1`（`rsi_lib.run_cmd` 已内置）。
- **地雷**：**`benchmarks/flows/gp_agent.run_ieda` 不锁线程**（它 `copy()` 环境）。
  我传过 `RSI_OMP_THREADS`，**而运行时读的是 `OMP_NUM_THREADS`** —— 名字不对，等于没锁，
  每个进程吃了 **128 线程**。**用哪个入口启动，决定了锁没锁上。**
- **验证**：`ls /proc/<pid>/task | wc -l` 必须是 1。

### 7.4 CPU 集字符串超过 `nproc` 会静默失败

> 传 `600-663`、`640-703` 而机器只有 512 核 → `taskset` 失败 → **所有拥塞测量静默失效**，
> 比值里只剩线长。**已发生两次。**
- **正解**：每次启动**核对 CPU 集与 `nproc`**。

### 7.5 进程清理必须"列出验证"，不能"发个 kill 就当成功"

- **症状**：`pkill -f <二进制名>` **匹配不到经包装器拉起的进程**，
  于是"已杀掉"的 SR-17 又跑了 74 分钟。
- **正解**：**按 PID 杀，然后 `ps` 列表核实**。

### 7.6 磁盘与水货清理

- `/` 长期 **99–100%**（3.4T/3.6T），**大量是他人账号占用**。
- **后果**：自己的测量产物**被清理掉过**（原版 iEDA 的 15 设计结果、时序基线文件都丢过，必须重跑）。
- **正解**：**重要产物及时写入 git 或在文档里留下可复算的脚本**；不要把结论只放在 `runs/` 里。

### 7.7 参考 DEF 必须合法化

- 直接用 Innovus 原始 DEF 计分，会使其拥塞被**高估 2.0–2.7 倍**。
- **正解**：参考也要跑一遍 LG（`runs/standingB/<design>/ref/` 就是合法化后的参考）。
